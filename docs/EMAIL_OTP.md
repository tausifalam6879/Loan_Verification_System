# Email OTP Setup

The OTP code is generated by the Spring Boot backend. Local development supports SMTP or a console fallback. Hosted deployments can use Resend or the Gmail API over HTTPS because Render Free blocks outbound SMTP ports.

The frontend reads `/api/users/auth-config` and enables only channels whose provider credentials and sender are actually ready.

## Local Development OTP

Use this mode when you do not have SMTP credentials yet:

```powershell
$env:APP_OTP_ENABLED="true"
$env:APP_MAIL_ENABLED="false"
$env:APP_OTP_CONSOLE_FALLBACK_ENABLED="true"

.\mvnw.cmd spring-boot:run
```

After clicking `Send OTP`, check the backend terminal for a line like:

```text
Development OTP for user@example.com [LOGIN]: 123456
```

## Local Gmail SMTP Setup

1. Open your Google account security settings.
2. Enable 2-Step Verification.
3. Create a Gmail App Password.
4. Use that app password as `SMTP_PASSWORD`.

Do not use your normal Gmail password.

## Start Local Backend With Email OTP

Run these commands in PowerShell from the project root:

```powershell
$env:APP_OTP_ENABLED="true"
$env:APP_OTP_CONSOLE_FALLBACK_ENABLED="false"
$env:APP_MAIL_ENABLED="true"
$env:SMTP_HOST="smtp.gmail.com"
$env:SMTP_PORT="587"
$env:SMTP_USERNAME="your-email@gmail.com"
$env:SMTP_PASSWORD="your-16-character-gmail-app-password"

.\mvnw.cmd spring-boot:run
```

Keep that backend terminal running.

## Render Email OTP With Resend

Do not use Gmail SMTP on a Render Free service. Configure these environment variables in the `fintrack-api` service instead:

```text
APP_OTP_ENABLED=true
APP_OTP_CONSOLE_FALLBACK_ENABLED=false
APP_MAIL_ENABLED=true
APP_MAIL_PROVIDER=resend
APP_MAIL_FROM=FinTrack <login@your-verified-domain.com>
RESEND_API_KEY=re_your_api_key
```

Create the API key in Resend and verify the domain used by `APP_MAIL_FROM`. Keep the API key only in Render's secret environment settings.

## Render Email OTP With Gmail API (No Domain)

The Gmail API provider sends from one authorized Gmail account to arbitrary recipients without requiring a custom sender domain. It uses only the narrow `gmail.send` OAuth scope.

1. Create a Google Cloud project and enable the Gmail API.
2. Configure the OAuth consent screen and add the sender Gmail account as a test user.
3. Create a Web application OAuth client with this authorized redirect URI:

   ```text
   https://developers.google.com/oauthplayground
   ```

4. In the [OAuth 2.0 Playground](https://developers.google.com/oauthplayground/), enable **Use your own OAuth credentials**, use **Offline** access, and authorize this scope:

   ```text
   https://www.googleapis.com/auth/gmail.send
   ```

5. Exchange the authorization code and copy the refresh token into Render. Configure:

   ```text
   APP_OTP_ENABLED=true
   APP_OTP_CONSOLE_FALLBACK_ENABLED=false
   APP_MAIL_ENABLED=true
   APP_MAIL_PROVIDER=gmail-api
   APP_MAIL_FROM=FinTrack <yourgmail@gmail.com>
   GMAIL_CLIENT_ID=your-google-oauth-client-id
   GMAIL_CLIENT_SECRET=your-google-oauth-client-secret
   GMAIL_REFRESH_TOKEN=your-google-oauth-refresh-token
   ```

Store all three OAuth values only as Render secrets. Never commit or paste them into chat. A Google OAuth app left in **Testing** normally issues a refresh token that expires after seven days for Gmail scopes; plan to reauthorize or complete the appropriate production OAuth setup before relying on it long term.

## Render Mobile and WhatsApp OTP With Twilio

Configure these environment variables in the `fintrack-api` service:

```text
APP_OTP_ENABLED=true
APP_SMS_ENABLED=true
APP_WHATSAPP_ENABLED=true
APP_SMS_DEFAULT_COUNTRY_CODE=+91
TWILIO_ACCOUNT_SID=ACxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
TWILIO_AUTH_TOKEN=your-secret-token
TWILIO_SMS_FROM=+12025550123
TWILIO_WHATSAPP_FROM=whatsapp:+14155238886
```

`TWILIO_SMS_FROM` must be an SMS-capable Twilio sender. For the WhatsApp sandbox, the receiving number must first join the sandbox; production WhatsApp senders must be approved in Twilio. The app accepts E.164 numbers and also expands a plain 10-digit Indian number with `+91` by default.

## IntelliJ Run Configuration

If you run the backend from IntelliJ:

1. Open `Run > Edit Configurations`.
2. Select the Spring Boot run configuration.
3. Add these environment variables:

```text
APP_OTP_ENABLED=true
APP_OTP_CONSOLE_FALLBACK_ENABLED=false
APP_MAIL_ENABLED=true
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=your-email@gmail.com
SMTP_PASSWORD=your-16-character-gmail-app-password
```

4. Save and run the backend again.

## Frontend Flow

When OTP or a specific provider is disabled, the frontend disables that channel and keeps password login available.

When OTP is enabled without SMTP, the frontend shows a success message and the OTP is available in the backend console.

Register:

1. Open `http://localhost:3000/#/register`.
2. Enter full name, email, and password.
3. Click `Send OTP`.
4. Check that email inbox or spam folder.
5. Enter the 6-digit OTP.
6. Click `Verify`.
7. Click `Register`.

Login:

1. Open `http://localhost:3000/#/login`.
2. Enter email and password.
3. Click `Send OTP`.
4. Enter the OTP received by email.
5. Click `Verify`.
6. Click `Login`.

## Troubleshooting

### An OTP tab is disabled

Check that the backend was started with:

```text
APP_OTP_ENABLED=true
```

Restart backend after setting those variables.

For local SMTP email delivery, also set:

```text
APP_MAIL_ENABLED=true
SMTP_USERNAME=your-email@gmail.com
SMTP_PASSWORD=your-gmail-app-password
```

For Render, use either the Resend or Gmail API variables above. The `/api/users/auth-config` response should show the configured channel as `true` after restarting the service.

### OTP email is not received

Check:

- Gmail App Password is correct.
- 2-Step Verification is enabled in Gmail.
- `SMTP_USERNAME` is the same Gmail account.
- Inbox and spam folder.
- Backend terminal for the exact error message.

### Login/Register says OTP verification required

OTP is enabled, but the OTP was not verified before pressing login/register. Send OTP, enter the code, click verify, then submit.
